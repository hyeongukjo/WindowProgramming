# WindowProgramming Project


컴퓨터 속 세계에서 벌어지는 병맛과 진지함을 넘나드는 **'디버그 용사: Windows File Dungeon DX'**의 10단계 스토리라인입니다. 이 스토리는 제공된 파일 데이터와 NPC 설정을 기반으로 하며, 최종적인 반전 요소를 포함하고 있습니다[cite: 3, 4, 7].

---

## 🖥️ 전체 시놉시스: "누가 내 프로젝트를 망쳤나"
어느 날, 바탕화면의 **'Final_Project_REAL_LAST.exe'**가 사라졌습니다[cite: 4]. 시스템 가이드인 **NPC 404호**는 이 사건이 단순한 오류가 아니라, 시스템 내부 파일들이 던전화되어 발생한 '파일 반란'이라고 주장합니다[cite: 3, 7]. 용사는 10개의 던전을 돌며 패치 조각을 모으고, 사라진 과제 파일의 행방을 추적해야 합니다[cite: 3, 4].

## 📂 스테이지별 스토리 전개 (10 Stages)

| 단계 | 던전 파일 및 위치[cite: 3] | 주요 Boss 및 NPC[cite: 3, 7] | 스토리 로그 (기믹 및 힌트) |
| :-- | :--- | :--- | :--- |

| **02** | **Popup_ErrorZone.dll** | **오류창 여왕 Exception** | 끊임없이 뜨는 오류 메시지들. 여왕은 "우리를 무시하고 X만 누른 자를 찾으라"며 경고합니다[cite: 4]. |
| **03** | **$Recycle.Bin_Cache.zip** | **휴지통 소녀 Binny** | 버려진 기록들이 괴물이 된 곳입니다. Binny는 아이템을 팔며 "버려진 로그 파일은 모든 것을 기억한다"는 중요한 단서를 줍니다[cite: 3, 7]. |
| **04** | **Windows_Update_Lab.patch** | **PatchMan** | 99%에서 멈춘 업데이트 진행률. 범인이 패치를 일부러 늦춰 시스템 최적화를 방해하고 있다는 사실이 드러납니다[cite: 3, 4]. |
| **05** | **ControlPanel_Settings.cpl** | **설정 집사 Panel** | 제어판 성벽. 누군가 관리자 권한을 도용해 시스템 설정을 멋대로 바꾸고 있습니다. 범인은 '권한'을 가진 존재입니다[cite: 3, 4]. |
| **06** | **Network_PortTunnel.net** | **패킷 선장 Ping** | 외부 패킷으로 위장한 침입 흔적을 발견합니다. 하지만 선장은 "공격은 내부 네트워크망에서 시작되었다"고 증언합니다[cite: 4]. |
| **07** | **Registry_HiveArchive.reg** | **레지스트리 사서 Regi** | 시스템의 기억 장소. 누군가 '실행 경로'를 조작해 과제 파일을 다른 곳으로 빼돌린 레지스트리 키를 찾아냅니다[cite: 3, 4]. |
| **08** | **Driver_VaultDevice.drv** | **드라이버 정비공 Driver-K** | 하드웨어 충돌을 핑계로 시스템 로그를 삭제하려던 범인의 흔적을 잡습니다. 진범의 정체가 좁혀집니다[cite: 3, 4]. |
| **09** | **System32_KernelGuard.sys** | **커널 수호자 Kernel** | 마지막 방어선. 수호자는 "가장 믿었던 관리자가 가장 큰 오류를 범했다"며 용사의 자격을 시험합니다[cite: 3, 4]. |
| **10** | **BSOD_DragonFault.bsod** | **Blue Screen Dragon** | 최종 결전지. 블루스크린 드래곤을 처치하면 드디어 사라진 과제 파일의 정체와 마주하게 됩니다[cite: 3, 4]. |

## ⚠️ 반전과 결말: "범인은 바로 너"

10스테이지의 드래곤을 처치하면 **'범인 추리'** 화면이 나타납니다[cite: 4]. 하지만 수집된 힌트(Update 지연, 파일명 남발, 휴지통 정리 실패)가 가리키는 진범은 NPC가 아닌 **사용자(Player)** 본인의 나쁜 습관입니다[cite: 4].

*   **1차 엔딩:** 가짜 범인을 지목하면 Update 아저씨를 체포하며 끝납니다[cite: 4].
*   **진 엔딩 (11단계):** 자신의 과오를 인정하면 찐 최종 던전 **'UserCore_TrueFault.exe'**가 해금됩니다[cite: 3]. 이를 클리어하면 "최고의 디버깅은 자기 점검"이라는 교훈과 함께 과제 파일 **'REAL_LAST_FINAL_FIXED.exe'**를 복구하며 끝이 납니다[cite: 4].

## 💡 개발 팁
*   **NPC 대사 활용:** 스테이지가 끝날 때마다 **NPC 404호**의 독설을 섞어주면 '병맛' 컨셉이 살아납니다[cite: 4, 7].
*   **동행 선택:** 각 스테이지 종료 후 구출한 파일(예: Searchy.exe)을 데려갈지 말지 선택하게 하여, 마지막 스테이지의 난이도나 엔딩 대사에 영향을 주도록 설계하세요[cite: 4].

이 스토리라인에서 보스 몬스터의 특정 공격 패턴(예: 99% 멈춤 공격, 팝업 도배 공격)을 더 구체화해 볼까요?

제안해주신 아이디어는 게임의 몰입도를 극대화할 수 있는 매우 훌륭한 기획입니다! NPC 404호와의 상호작용(대화 선택지, 파일 처우 등)에 따라 **'거짓 힌트(남 탓)'**와 **'진실 힌트(플레이어 암시)'**가 나뉘고, 이 서사가 쌓여 마지막에 **소름 돋는 반전**으로 이어지는 구조를 설계해 드리겠습니다.

현재 코드의 `CompanionChoice`(파일 동행/방치/삭제)와 `RewardChoice`(무기강화/힌트)[cite: 4] 시스템을 활용하여 스크립트를 구성했습니다.

## ⚙️ 상호작용 시스템 설계: "카르마(업보)와 힌트의 질"

플레이어가 스테이지 클리어 후 어떤 선택을 하느냐에 따라 NPC 404호의 태도와 제공하는 힌트의 퀄리티가 달라집니다.

*   **😈 나쁜 상호작용 (파일 삭제 + 무기 강화 위주):**
    *   **NPC 반응:** "역시 힘이 최고죠. 생각하길 포기하셨군요."
    *   **힌트 퀄리티:** **[거짓/표면적 힌트]** 다른 NPC들(오류창, 업데이트 관리자 등)을 범인으로 몰아가는 뻔한 단서만 제공합니다.
*   **😇 좋은 상호작용 (파일 동행 + 힌트 탐구 위주):**
    *   **NPC 반응:** "오, 데이터를 아낄 줄 아는 분이군요. 그럼 조금 더 깊은 로그를 보여드리죠."
    *   **힌트 퀄리티:** **[진실/심층 힌트]** 점점 '키보드 밖의 누군가'를 가리키는 서늘한 단서를 제공합니다.

### 💻 코드 구현을 위한 조언
이 스토리를 구현하려면 `MainForm.cs`의 상호작용 관련 변수들을 조금 다듬으면 됩니다.

1.  **카르마 변수 추가:** `MainForm`에 `int truthScore = 0;` 을 선언합니다.
2.  **점수 누적:** `ResolveCompanionChoice`에서 "take(동행)" 선택 시 `truthScore++`, `ResolveRewardChoice`에서 힌트 선택 시 `truthScore++` 처리합니다[cite: 4].
3.  **동적 힌트 제공:** `GameData.GetHintText(DungeonType type, int truthScore)` 메서드를 수정하여, `truthScore`가 높으면 위의 [진실 힌트]를, 낮으면 NPC를 탓하는 [거짓 힌트]를 리턴하도록 만드세요.

이 서사를 적용하면 플레이어는 단순한 액션 게임을 넘어서, 시스템과 소통하며 자신의 잘못(?)을 참회하는 엄청난 몰입감을 경험하게 될 것입니다!
