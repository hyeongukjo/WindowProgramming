핵심 컨셉
Stage 7은 플레이어가 처음으로 자신의 이전 행동 기록을 마주하는 조용한 탐색형 일반 스테이지이다.
이 스테이지는 플레이어의 정체를 직접 밝히는 구간이 아니라, 지금까지의 행동이 시스템 기록으로 남아 있다는 사실을 보여주는 구간이다.
레지스트리는 Windows 내부의 설정값, 실행 기록, 프로그램 경로, 사용자별 환경 정보가 모이는 공간이므로 후반부 반전을 위한 암시를 넣기에 가장 자연스럽다.
핵심 감각
사용자 정체를 설명하는 것이 아니라, 사용자의 습관과 선택이 기록으로 남아 있다는 사실을 플레이어가 스스로 눈치채게 한다.
Stage 7에서 지켜야 할 점
Stage 7부터는 후반부 반전을 위한 암시를 본격적으로 넣는다.
단, “범인은 사용자다”, “당신이 시스템을 망가뜨렸다” 같은 직접 설명은 금지한다.
암시는 대사보다 레지스트리 값, 최근 실행 기록, 프로필 이름, 선택 기록으로 보여준다.
전투는 무작정 적을 처치하는 방식보다 정리할 값과 보관할 값을 구분하는 탐색형 전투로 구성한다.
Windows Recovery Assistant는 이전보다 더 차분하고 기계적인 톤을 유지한다.
플레이어가 입력한 복구 프로필 이름을 다시 등장시켜야 한다.
Stage 8 Popup Error 미궁으로 이어질 수 있도록 “남은 예외 메시지”를 남긴다.
2. 스테이지 진행 구조
진행 요약
Stage 7은 Stage 6에서 시스템 충돌을 일시적으로 회피한 뒤, 원인 추적을 위해 Registry Hive.exe를 실행하면서 시작된다.
플레이어는 Windows XP 레지스트리 편집기처럼 보이는 공간에 진입한다.
처음에는 시스템 설정값을 확인하는 작업처럼 보이지만, 탐색 중 이전 스테이지에서 플레이어가 했던 선택과 행동이 기록으로 남아 있음을 발견한다.

HKEY 트리 구조 확인
Broken Key, Duplicate Value, Orphan Entry 정리

이전 스테이지 행동 기록 확인
복구 프로필 이름 재등장
정리 / 보관 / 검사 선택 이벤트
레지스트리 백업 생성
Popup Error 미궁으로 연결
비고
Stage 7은 일반 스테이지이지만, 이전 일반 스테이지보다 전투 밀도는 낮추고 조사와 선택 비중을 높인다.
감정 흐름은 “조용한 의심”이다. 플레이어는 설명을 듣는 것이 아니라 기록을 보면서 불편함을 느껴야 한다.

4. Registry Hive 화면 구성
장면 목적
Registry Hive 보관소의 시각적 분위기를 보여주는 장면이다.
레지스트리 편집기 화면을 실제 게임 공간처럼 확장한다.
화면 구성
화면 중앙에는 Windows XP 스타일 Registry Editor 창이 크게 열린다.
창은 좌우로 나뉘어 있다.
왼쪽에는 트리 구조가 있고, 오른쪽에는 선택된 키의 값 목록이 표시된다.
Registry Editor - 왼쪽 트리
HKEY_CLASSES_ROOT
HKEY_CURRENT_CONFIG
HKEY_LOCAL_MACHINE
HKEY_USERS
HKEY_CURRENT_USER
Registry Editor - 오른쪽 값 목록
Name              Type          Data
LastRun           REG_SZ        ...
UpdateDelay       REG_DWORD     ...
PortBlocked       REG_DWORD     ...
RestartPending    REG_DWORD     ...
화면 연출
왼쪽 트리 구조는 미로처럼 깊게 이어진다.
레지스트리 키는 폴더처럼 열리고 닫히며, 값 항목은 작은 서랍이나 카드처럼 표시된다.
전체 색감은 Stage 6보다 어둡지는 않지만, 차갑고 조용하다.
일부 값은 깨진 글자로 표시되거나, 마우스를 올리면 이전 스테이지의 짧은 기록처럼 보인다.
비고
HKEY_CURRENT_USER는 실제 Windows 레지스트리 구조상 자연스럽게 등장할 수 있다. 다만 Stage 7에서는 이를 강조하지 않고 목록 중 하나처럼 지나가게 한다.
5. Windows Recovery Assistant 안내
장면 목적
Registry Hive의 성격을 설명하고, Assistant의 톤이 더 차분하고 기계적으로 변했음을 보여준다.
화면 구성
화면 오른쪽 아래에 Windows Recovery Assistant 알림창이 열린다.
알림창 왼쪽에는 CRT 모니터 머리의 Windows Recovery Assistant 캐릭터가 표시된다.
모니터 화면에는 웃는 얼굴이 아니라 평평한 안내 표정 또는 말줄임표가 표시된다.
알림창
Windows Recovery Assistant
Registry Hive에 진입했습니다.
이곳에는 시스템 설정값과 실행 기록이 저장되어 있습니다.
값을 임의로 수정하지 않도록 주의해주세요.
[확인]
진행
플레이어가 [확인]을 누르면 왼쪽 레지스트리 트리가 자동으로 한 단계 펼쳐진다.
Windows Recovery Assistant
기록은 복구에 필요합니다.
삭제하지 말고 확인만 진행해주세요.
[확인]
비고
Stage 7부터 Assistant는 밝은 감탄사를 거의 사용하지 않는다.
문장은 짧고 기능적이어야 하며, “기록은 남는다”는 느낌을 직접 설명하지 않고 분위기로 전달한다.
6. 일반 전투 구간
장면 목적
Registry Hive 내부에서 레지스트리 키와 값들이 적으로 변형되는 일반 전투 구간이다.
Stage 7의 전투는 모든 대상을 처치하는 방식보다, 정리할 것과 보관할 것을 구분하는 방식으로 구성한다.
전투 대상
적 / 개체
역할
Broken Key
깨진 레지스트리 키. 금이 간 폴더 키 아이콘처럼 보이며, 주변 값들을 꼬이게 만든다.
Duplicate Value
중복된 값. 같은 이름의 값이 여러 개로 분열되며 진짜 값과 가짜 값이 섞인다.
Orphan Entry
연결이 끊긴 기록. 삭제된 프로그램의 흔적처럼 느리게 따라오며 오래된 실행창을 잠깐 띄운다.
Recent Trace
최근 실행 흔적. 직접 공격하기보다 조사해야 하는 대상이며, Stage 7의 핵심 암시를 담당한다.
전투 방식
플레이어는 Recovery Program 캐릭터를 움직여 레지스트리 키와 값에 접근한다.
기본 공격과 스킬을 사용할 수 있지만, 일부 기록 개체는 무작정 삭제하면 안 된다.
Stage 7부터는 단순 공격 외에 선택 버튼이 등장한다.
선택 버튼 예시
[정리] [검사] [보관] [무시]
비고
구체적인 공격 패턴, 피해량, 선택 결과는 아직 확정하지 않는다.
이 문서에서는 탐색형 전투 방향과 암시 방식만 우선 정리한다.
7. 최근 실행 기록 발견
장면 목적
플레이어가 앞 스테이지에서 했던 행동들이 레지스트리 기록으로 남아 있음을 처음 보여주는 장면이다.
이 장면은 Stage 7의 핵심 암시 장면이다.
진행
플레이어가 Registry Hive 내부를 탐색하다가 RecentActions 키를 발견한다.
해당 키를 조사하면 오른쪽 값 목록에 이전 스테이지의 행동 기록이 표시된다.

Stage01_DesktopCleanup      Completed
Stage02_DriverRecovery       Completed
Stage03_UpdateReminder       Delayed
Stage04_AccessPermission     Allowed
Stage05_PortDecision         Blocked
Stage06_CrashRecovery        Interrupted
Windows Recovery Assistant 반응
Windows Recovery Assistant
복구 과정 중 생성된 기록입니다.
문제가 있는 값만 정리하면 됩니다.
[확인]
플레이어가 느껴야 하는 감정
플레이어는 “이거 내가 앞에서 했던 선택들 아닌가?”라고 느껴야 한다.
하지만 Assistant는 이를 특별한 단서처럼 설명하지 않는다.
비고
이 장면에서는 “당신의 행동입니다”라고 직접 말하지 않는다.
기록 자체가 암시 역할을 해야 한다.
8. 복구 프로필 이름 재등장
장면 목적
Stage 1에서 플레이어가 입력한 복구 프로필 이름을 시스템 깊은 곳에서 다시 보여주는 장면이다.
이름 입력이 단순 닉네임이 아니라 시스템 기록과 연결되어 있다는 느낌을 준다.

LastSession        REG_SZ      Not Closed Properly

Assistant가 너무 아무렇지 않게 넘어가는 것이 오히려 불편하게 느껴져야 한다.
여기서도 “사용자 이름”이라는 표현은 사용하지 않는다.
9. 선택 이벤트: 정리할 값과 남길 값
장면 목적

플레이어 행동이 기록으로 남는다는 암시를 강화한다.
진행

검사

보관

비고

아직 Assistant가 기록을 숨기거나 강압적으로 지키는 느낌까지는 주지 않는다.
10. 일반 전투 종료 흐름

하지만 이 의미를 직접 설명하지 않는다.

Stage 8은 보스 스테이지이다.
Stage 7에서 레지스트리 기록을 건드린 결과, 숨겨져 있던 예외 메시지와 무시된 오류창들이 한꺼번에 튀어나오는 흐름으로 이어진다.

13. Stage 7 기획 메모
핵심 감각
핵심 감각
플레이어가 자신의 이전 행동 기록을 처음 마주하는 조용한 탐색형 일반 스테이지
정체를 설명하지 않고, 기록을 통해 의심을 만들기
분위기 변화
Stage 6은 시스템이 실제로 멈출 뻔한 위험감을 보여줬다.
Stage 7은 그 직후 액션을 줄이고, 기록과 흔적을 확인하는 조용한 의심의 구간으로 전환한다.
이 스테이지부터는 플레이어가 “내가 지금까지 한 행동들이 시스템에 남아 있다”는 감각을 느끼기 시작해야 한다.
암시 방식
앞 스테이지에서 플레이어가 한 행동 기록을 보여준다.
Stage 1에서 입력한 복구 프로필 이름을 다시 보여준다.
삭제하면 안 되는 Recent Trace를 등장시킨다.
Assistant가 기록을 너무 당연하게 취급하도록 만든다.
직접 설명 대신 레지스트리 값과 파일명으로 암시한다.
NPC 표현 방식
Windows Recovery Assistant는 Stage 7에서 확실히 차분하고 기계적인 톤으로 변한다.
친절함은 남아 있지만, 플레이어의 불편함에 공감하기보다 기록 확인과 복구 절차를 우선한다.
전투 관련 메모
Stage 7은 일반 스테이지이므로 일반 전투가 존재한다.
다만 전투는 단순 처치형보다 탐색형, 선택형으로 구성한다.
구체적인 공격 패턴, 피해량, 선택 결과는 추후 전투 시스템 확정 단계에서 조정한다.
후반 회수 가능 요소
RecentActions 기록은 Stage 10에서 플레이어 행동 증거로 다시 등장할 수 있다.
Backup_RecoveryProfile_입력한이름.reg는 후반부에서 사용자 흔적처럼 재해석될 수 있다.
Stage 4의 AccessPermission = Allowed 기록은 “허용” 버튼 선택의 누적 증거가 될 수 있다.
Stage 5의 PortDecision = Blocked 기록은 연결을 차단한 흔적으로 회수 가능하다.
Stage 6의 CrashRecovery = Interrupted 기록은 충돌을 강제로 회피한 흔적으로 활용할 수 있다.
주의점
Stage 7부터 암시는 넣되, 정답 공개는 하지 않는다.
“너는 사용자다”, “네가 범인이다” 같은 직접 표현은 금지한다.
HKEY_CURRENT_USER는 등장해도 되지만 강조하지 않는다.
Assistant가 갑자기 적대적으로 변하면 안 된다. 아직은 절차를 우선하는 차가운 안내자 정도가 적절하다.
플레이어가 불편함을 느끼게 하되, 해석은 플레이어에게 맡긴다.
