Stage 8은 후반부로 본격 진입하는 보스 스테이지이다.
Stage 7에서 레지스트리 기록을 확인한 뒤, 그동안 닫고 무시했던 오류 메시지들이 한꺼번에 되살아난다.
처음에는 단순히 오류창이 많이 뜨는 코믹한 상황처럼 보이지만, 중반부터는 X 버튼이 함정이 되고 버튼 이름이 바뀌며 UI가 플레이어를 공격하기 시작한다.
보스 Exception Queen은 무시된 경고와 닫힌 오류창들의 집합체이다.
Stage 8의 핵심은 “닫았던 창들이 다시 열린다”는 감각이다.
Stage 8에서 지켜야 할 점
보스 스테이지이므로 일반 몹전은 넣지 않는다.
보스전 자체가 오류창 미궁과 UI 조작 중심으로 진행된다.
처음에는 팝업 개그처럼 시작하되, 점점 조작이 통제되지 않는 느낌으로 바뀐다.
Windows Recovery Assistant는 오류창을 계속 닫으라고 지시하며 점점 집착적으로 변한다.
Exception Queen은 플레이어가 그동안 눌렀던 [확인], [취소], [나중에], [닫기] 행동을 기억하는 듯한 대사를 한다.
“너는 사용자다”, “네가 시스템을 망가뜨렸다” 같은 직접 공개는 아직 하지 않는다.
Stage 9의 Temp Cache 동굴로 이어질 수 있도록, 오류 보고서가 임시파일로 남는 흐름을 만든다.
2. 스테이지 진행 구조
진행 요약
Stage 8은 Stage 7 클리어 후 생성된 Exception Report.exe를 실행하면서 시작된다.
처음에는 처리되지 않은 오류 기록을 확인하는 정상적인 오류 보고 창처럼 보인다.
하지만 오류창이 하나씩 늘어나고, 닫은 창이 다시 열리면서 화면 전체가 팝업 미궁으로 변한다.
플레이어는 오류창 사이를 이동하고, 잘못된 버튼을 피하면서 Exception Queen의 중심 오류창을 찾아야 한다.
보스전 후 오류창들은 격리되지만 완전히 사라지지 않고 UNSENT_REPORT.tmp라는 임시파일로 남아 Stage 9로 연결된다.

비고
Stage 8은 후반부 진입 지점이므로 암시를 적극적으로 넣어도 된다. 단, 반전의 정답을 직접 설명하지 않고, 오류창의 대사와 UI 붕괴를 통해 플레이어가 스스로 불편함을 느끼게 해야 한다.

4. Popup Error 미궁 화면 구성
장면 목적
오류창이 단순 UI가 아니라 벽, 문, 발판, 장애물로 변하는 Stage 8의 전투 공간을 보여준다.
화면 구성
처음에는 Windows XP 바탕화면 위에 작은 오류창 두세 개가 뜬다.
오류창은 서로 겹치기 시작하고, 닫힌 창은 다른 위치에서 다시 열린다.
오류창들이 화면 위에 쌓이면서 통로와 벽처럼 배치된다.
작업 표시줄에는 오류창 버튼이 계속 늘어나며, 화면 아래쪽이 점점 복잡해진다.
플레이어는 오류창 사이를 이동하며, 버튼과 창의 빈틈을 통해 보스에게 접근해야 한다.
필드 구성 요소
오류창: 벽과 장애물 역할을 한다.
X 버튼: 일부 창에서는 함정으로 작동한다.
[확인], [취소], [무시] 버튼: 발판이나 선택 지점처럼 사용된다.
작업 표시줄: 오류창 버튼이 쌓이며 스킬 UI 일부를 가릴 수 있다.
투명 오류창: 사라졌다가 다시 나타나는 미궁 요소로 사용된다.
중심 오류창: Exception Queen의 본체가 숨어 있는 핵심 창이다.
비고
Stage 8은 “맵을 탐험한다”기보다 “UI가 쌓여 만들어진 공간을 뚫고 간다”는 느낌이 중요하다.

6. 보스 등장: Exception Queen
장면 목적
Exception Queen이 닫히고 무시된 오류창들의 집합체라는 것을 보여주는 장면이다.
등장 연출
플레이어가 오류창 몇 개를 닫으면, 닫힌 창들이 완전히 사라지지 않고 화면 뒤쪽으로 밀려난다.
밀려난 창들이 서로 겹치며 하나의 큰 창 구조를 만든다.
작업 표시줄에 쌓인 오류창 버튼들이 동시에 깜빡인다.
화면 중앙에 다른 창보다 훨씬 큰 오류창이 열린다.
큰 오류창의 제목 표시줄에 Exception Queen이라는 이름이 표시된다.
보스 외형
여러 개의 Windows XP 오류창이 겹쳐진 왕관 형태의 보스이다.
중앙에는 큰 빨간 X 아이콘이 있다.
창 테두리는 파란색 XP 스타일이지만, 일부는 깨져 있거나 어긋나 있다.
버튼들이 몸체처럼 붙어 있으며, [확인], [취소], [무시], [나중에]가 계속 바뀐다.
보스가 움직일 때마다 작은 오류창들이 떨어져 나와 주변을 가린다.
체력이 낮아질수록 창 제목과 버튼 이름이 더 자주 깨진다.
X 오류창 / 보스 대사
Unhandled Exception
처리되지 않은 오류가 누적되었습니다.
닫힌 창을 복원합니다.
[확인]
X 오류창 / 보스 대사
Exception Queen
또 닫으려고?
항상 그렇게 했잖아.
[확인]
비고
Exception Queen은 “무시된 오류들의 집합”이다. 플레이어를 직접 고발하지는 않지만, 그동안의 행동을 기억하는 듯한 대사로 압박한다.
7. 보스전 구간
장면 목적
오류창을 닫고 버튼을 고르는 Windows UI 조작 자체가 전투가 되는 보스전을 진행한다.
전투 공간
전투는 오류창들이 겹쳐진 미궁 안에서 진행된다.
플레이어는 Recovery Program 캐릭터를 움직여 창 사이를 이동한다.
일부 창은 닫을 수 있지만, 일부 창은 닫으면 더 늘어난다.
Exception Queen의 본체는 여러 오류창 뒤에 숨어 있으며, 가짜 창과 진짜 창을 구분해야 접근할 수 있다.
보스 상태 표시
보스 상태
Exception Queen
HP: 미정
상태: 처리되지 않은 오류 누적
전투 목표
가짜 오류창과 진짜 오류창을 구분한다.
무작정 X 버튼을 누르지 않는다.
Exception Queen의 중심 오류창을 찾아낸다.
중심 오류창을 격리하여 오류창 폭주를 멈춘다.
전투 흐름
초반에는 오류창을 닫으며 길을 확보한다.
중반부터 X 버튼을 누르면 창이 복제되거나 다른 위치에 다시 열린다.
작업 표시줄에 오류창 버튼이 쌓이면서 플레이어의 화면 일부가 가려진다.
후반에는 버튼 이름이 바뀌고, 일부 버튼은 눌러도 다른 효과를 낸다.
플레이어는 단순히 닫는 것이 아니라, 어떤 창을 닫고 어떤 창을 격리할지 판단해야 한다.
비고
구체적인 피해량, 쿨타임, 보스 HP는 아직 확정하지 않는다. 이 문서에서는 UI 조작형 보스전의 흐름과 분위기를 우선 정리한다.
8. 임시 보스 패턴 방향
패턴 이름과 수치는 임시 방향이다. 추후 전투 시스템 확정 시 조정한다.
패턴
방향
Popup Flood
오류창이 여러 개 뜨며 플레이어의 이동 공간을 가린다. 일부 창은 닫을 수 있지만, 일부는 X 버튼을 누르면 두 개로 복제된다.
False Button
버튼 이름이 바뀐다. [확인] [취소]가 [확인] [확인]으로 바뀌거나, [닫기] [닫지 않음]처럼 혼란스럽게 변한다.
Taskbar Overflow
작업 표시줄에 오류창 버튼이 계속 쌓인다. 버튼이 너무 많아지면 플레이어의 스킬 UI 일부가 가려진다.
X Button Trap
X 버튼을 누르면 창이 닫히는 대신 다른 위치에 두 개가 생성된다. Stage 8부터 X 버튼이 항상 해결책이 아니라는 사실을 보여준다.
Error Echo
Stage 1~7의 행동 기록이 짧은 오류 문장으로 튀어나온다. 예: UpdateReminder = Delayed, PortDecision = Blocked, AccessPermission = Allowed, CrashRecovery = Interrupted.

보스 의미
Exception Queen은 단순한 악성 프로그램이 아니다.
Stage 1부터 플레이어가 닫고, 무시하고, 미룬 오류창과 경고 메시지들이 누적되어 만들어진 존재다.
그녀는 플레이어의 행동을 직접 고발하지는 않지만, “항상 그렇게 했잖아” 같은 대사로 행동의 반복을 암시한다.
NPC 표현 방식
Windows Recovery Assistant는 Stage 8부터 확실히 이상해진다.
알림창은 여전히 XP 스타일이지만, 대사가 점점 반복적이고 집착적으로 변한다.
Assistant는 오류창을 닫으라고 계속 지시하고, Exception Queen은 닫아도 사라지지 않는다고 말한다.
이 충돌을 통해 플레이어는 Assistant를 처음으로 의심할 수 있다.
전투 관련 메모
Stage 8은 보스 스테이지이므로 일반 몹전은 넣지 않는다.
전투는 UI 조작형 보스전으로 구성한다.
구체적인 공격 수치, 피해량, 쿨타임은 아직 확정하지 않는다.
닫기, 확인, 취소, 무시, 나중에 같은 UI 버튼을 전투 요소로 활용한다.
작업 표시줄, X 버튼, 오류창 제목 표시줄까지 모두 전투 공간의 일부로 사용한다.
후반 회수 가능 요소
오류창을 닫는 행동이 해결이 아니라 임시로 밀어낸 것뿐이었다는 점
오류 보고서를 보내지 않거나 나중에 미룬 선택
Stage 3~7의 행동 기록이 오류 문장으로 튀어나오는 연출
UNSENT_REPORT.tmp가 Stage 9의 Temp Cache 동굴로 이어지는 연결점
Assistant가 닫으라고 지시한 행동이 정말 옳았는지에 대한 의심
주의점
Stage 8에서는 암시를 적극적으로 넣어도 되지만, 최종 반전은 말하지 않는다.
“너는 사용자다”, “네가 시스템을 망가뜨렸다”, “복구 프로그램은 거짓이다” 같은 문장은 사용하지 않는다.
Exception Queen은 플레이어를 몰아붙이되, 정답을 설명하지 않는다.
UI 붕괴와 버튼 변화로 공포를 주되, 플레이어가 완전히 이해하는 것은 Stage 10까지 미룬다.
