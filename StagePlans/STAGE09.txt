STAGE 09 일반[Temp Cache 동굴]
스테이지 한 줄 요약
Stage 9는 플레이어가 삭제했다고 생각한 기록과 오류들이 임시파일 형태로 남아 있는 것을 확인하는 최종 직전 탐색형 일반 스테이지다.

핵심 컨셉
Stage 9는 마지막 일반 스테이지이며, Stage 10 최종전을 위한 증거 수집 구간이다.
Stage 8에서 Exception Queen을 격리했지만, 닫힌 오류창과 미전송 오류 보고서는 완전히 사라지지 않고 임시파일과 캐시 형태로 남아 있다.
플레이어는 오류 보고서, 최근 실행 기록, 복구 프로필 캐시, 차단 및 허용 기록을 정리하러 Temp Cache 동굴에 들어간다.
이곳의 파일들은 단순한 쓰레기 파일이 아니라, 플레이어가 이전 스테이지에서 선택한 행동들의 잔여물이다.
Stage 9의 핵심은 “삭제된 줄 알았던 것들이 아직 남아 있다”는 감각이다.
Stage 9에서 지켜야 할 점
일반 스테이지이지만 단순 전투보다 탐색과 기록 확인 비중을 높인다.
플레이어가 이전에 닫고, 연기하고, 차단하고, 허용했던 행동의 잔여물을 보여준다.
Stage 1에서 입력한 복구 프로필 이름은 “입력한 이름” 또는 “복구 프로필 이름”으로만 표현한다.
실제 사용자 이름은 문서나 예시에 넣지 않는다.
Stage 10의 멀티엔딩 입력을 준비할 수 있도록 보스 이름과 플레이어 입력 이름이 캐시 파일명으로 흩어져 있게 한다.
Windows Recovery Assistant는 더 차갑고 처리 중심적인 말투로 바뀐다.
정체 공개, “너는 사용자다”, “네가 시스템을 망가뜨렸다” 같은 직접 설명은 아직 하지 않는다.
2. 스테이지 진행 구조
진행 요약
Stage 9는 Stage 8에서 격리된 오류 보고서가 임시 저장소에 남아 있다는 알림으로 시작된다.
플레이어는 Temporary Files, ErrorReport, Recent, Cache 같은 폴더 조각으로 이루어진 동굴형 공간에 진입한다.
동굴 안에는 삭제된 줄 알았던 파일 조각, 미전송 오류 보고서, 최근 실행 잔상, 복구 프로필 캐시가 남아 있다.
플레이어는 파일을 열어볼지, 삭제할지, 보관할지 선택하며 전투와 탐색을 진행한다.
마지막에는 Cache Heap을 정리하고, 정리된 항목들이 모두 Recycle Bin으로 이동하면서 Stage 10으로 연결된다.
주요 진행 순서
Temp Cache 진입
임시파일 더미 탐색
삭제되지 못한 파일 조각들과 전투
미전송 오류 보고서 발견
복구 프로필 이름이 들어간 캐시 발견
삭제 / 보관 / 열기 선택 이벤트
최근 실행 잔상 확인
Cache Heap 정리
정리된 항목이 Recycle Bin으로 이동
Stage 10 Recycle Bin 던전으로 연결
비고
Stage 9는 Stage 10의 진실 공개 직전 단계이다. 따라서 암시는 강하게 넣되, 결론은 플레이어가 직접 Stage 10에서 확인하게 해야 한다.

4. Temp Cache 동굴 화면 구성
장면 목적
삭제된 줄 알았던 파일들이 임시 저장소 안에 쌓여 있다는 느낌을 주는 장면이다.
화면 구성
Windows XP 탐색기 창이 화면 중앙에 크게 열린다.
창 제목은 Temp Cache로 표시된다.
주소창에는 다음과 같은 경로가 나타난다.
주소창
C:\Documents and Settings\...\Local Settings\Temp
경로 중간은 일부 생략되거나 깨진 것처럼 보인다. 실제 사용자명을 직접 표시하지 않는다.
동굴형 공간
임시파일 더미가 바위처럼 쌓여 있다.
오류 보고서 조각이 종이 더미처럼 흩어져 있다.
브라우저 캐시와 이미지 썸네일이 벽면에 붙어 있다.
최근 실행 기록 아이콘이 흐릿한 그림자처럼 나타났다 사라진다.
일부 파일명은 깨져 있거나 확장자만 보인다.
전체 색감은 회색, 어두운 파란색, 누런 임시 폴더 색을 섞어 표현한다.
비고
Stage 9는 공포를 직접적으로 보여주기보다, 현실적인 파일 흔적이 너무 많이 남아 있는 불편함을 강조한다.

6. 일반 전투 대상
장면 목적
Temp Cache 동굴에 남아 있는 임시파일과 캐시 흔적을 전투 및 탐색 대상으로 보여준다.
이름
역할
설명
Temp Fragment
임시파일 조각
작은 종이 파일 조각 형태. 체력이 낮고 많이 등장한다. 삭제하면 잠시 사라졌다가 다른 위치에서 다시 나타날 수 있다.
Cache Leech
캐시 찌꺼기
브라우저 캐시나 이미지 썸네일 같은 적. 플레이어에게 달라붙어 이동 속도를 늦춘다.
Unsent Report
미전송 오류 보고서
직접 공격하기보다 열어볼 수 있는 오브젝트. Stage 8의 오류창 대사 일부를 다시 보여준다.
Recent Ghost
최근 실행 기록의 잔상
이전 스테이지에서 실행한 파일 아이콘들이 흐릿하게 나타나는 흔적. 전투 대상보다 연출 오브젝트에 가깝다.
Cache Heap
마무리 대형 적
임시파일 더미가 뭉친 덩어리. Stage 9의 마지막 정리 대상으로 사용한다.
비고
Stage 9는 일반 스테이지이지만, 모든 대상을 단순히 처치하는 방식으로 구성하지 않는다. 열기, 삭제, 보관, 무시 같은 선택을 섞어 탐색형 전투 감각을 만든다.
7. 탐색형 일반 전투 흐름
장면 목적
일반 전투와 기록 탐색을 섞어 Stage 10 직전의 불안감을 쌓는 구간이다.
전투 흐름
플레이어는 Recovery Program 캐릭터를 움직여 임시파일 더미 사이를 이동한다.
Temp Fragment와 Cache Leech는 일반 적처럼 등장해 플레이어를 방해한다.
Unsent Report와 RecoveryProfile.cache 같은 파일은 공격보다 조사와 선택을 통해 처리한다.
Recent Ghost는 플레이어에게 직접 피해를 주기보다, 이전 스테이지의 실행 흔적을 보여주는 역할을 한다.
플레이어가 파일을 처리할 때마다 화면에 짧은 확인창이 뜬다.
선택형 파일 처리
! 시스템 메시지
파일 처리
이 항목을 삭제하시겠습니까?
[삭제] [보관] [열기]
선택 의미
[삭제]는 파일을 휴지통으로 이동시킨다.
[보관]은 파일을 그대로 두고 지나간다.
[열기]는 파일 안의 기록을 확인한다.
Stage 9에서는 플레이어가 삭제를 반복하게 만들되, 삭제한 항목이 완전히 사라지지 않고 Recycle Bin으로 이동한다는 점을 보여준다.

12. 마무리 전투: Cache Heap
장면 목적
Stage 9의 일반 전투를 마무리하고, 모든 흔적이 Recycle Bin으로 이동하는 흐름을 만든다.
화면 구성
동굴 가장 안쪽에 임시파일 더미가 뭉친 Cache Heap이 나타난다.
Cache Heap은 보스가 아니라 Stage 9의 마지막 정리 대상이다.
형태

전투 흐름
플레이어는 Cache Heap 주변의 작은 파일 조각을 정리한다.
Cache Heap은 직접적인 공격보다 화면을 가리고 이동을 방해하는 방식으로 압박한다.
일정 단계가 지나면 [정리 실행] 또는 [삭제 항목 이동] 상호작용이 열린다.
플레이어가 상호작용을 실행하면 파일 더미가 휴지통으로 이동한다.

13. Stage 9 클리어 연출
장면 목적
임시 저장소 정리가 끝났지만, 모든 것이 완전히 삭제된 것이 아니라 Recycle Bin으로 이동했음을 보여준다.
진행
Cache Heap이 무너지며 임시파일 조각들이 한 방향으로 빨려 들어간다.
화면 오른쪽 아래에 휴지통 아이콘이 크게 표시된다.
파일 조각들은 삭제되는 것이 아니라 휴지통 안으로 이동한다.
Temp Cache 동굴의 바닥은 비어 가지만, 휴지통 아이콘은 점점 무거워 보인다.

연결 설명
Stage 10은 최종 스테이지이다.
Stage 9에서 정리한 임시파일, 오류 보고서, 최근 실행 기록, 보스 기록, 복구 프로필 캐시가 모두 Recycle Bin에 모인다.
플레이어는 최종적으로 무엇을 삭제할 것인지 직접 입력하게 된다.
Stage 1에서 입력한 복구 프로필 이름을 입력하면 진엔딩으로 이어진다.
다른 보스 이름이나 잔여 프로세스 이름을 입력하면 일반 엔딩 또는 루프성 엔딩으로 이어질 수 있다.
15. Stage 9 기획 메모

핵심 감각

임시 저장소에 남아 있고,
그 흔적이 최종 스테이지의 삭제 대상 후보로 쌓여 가는 구간
스토리 진행 요약
플레이어는 Stage 8에서 오류창을 격리했지만, 오류 보고서와 캐시가 Temp Cache에 남아 있음을 확인한다.
이곳에서 플레이어는 이전 스테이지의 실행 기록과 선택 기록을 다시 마주한다.
입력한 복구 프로필 이름은 캐시 파일 안에 남아 있고, 보스 이름들은 임시파일명으로 흩어져 있다.
플레이어는 아직 자신이 무엇을 삭제해야 하는지 정확히 알지 못하지만, Stage 10에서 입력할 후보들을 무의식적으로 보게 된다.
마지막에는 모든 정리 항목이 Recycle Bin으로 이동하며 최종 정리 단계로 넘어간다.
Assistant 변화
Stage 9의 Windows Recovery Assistant는 더 이상 밝게 농담하지 않는다.
삭제, 정리, 기록 축소 같은 표현을 자주 사용한다.
“열어보지 않아도 됩니다. 삭제하면 정리됩니다.” 같은 문장으로 플레이어가 확인보다 삭제를 선택하도록 유도한다.
아직 공격적으로 붙잡지는 않지만, 복구보다 통제를 우선하는 느낌이 강해진다.
후반 회수 가능 요소
UNSENT_REPORT.tmp는 Stage 8의 오류창이 완전히 사라지지 않았음을 보여준다.
RecoveryProfile.cache는 Stage 1의 이름 입력이 단순 닉네임이 아니었음을 암시한다.
Recent Ghost는 플레이어가 실행한 스테이지 아이콘들이 기록으로 남았음을 보여준다.
cache_Driver-K.tmp, report_High-Kernel.tmp, dump_BSOD.tmp 등은 Stage 10의 일반 엔딩 입력 후보가 된다.
profile_입력한 이름.cache는 진엔딩 입력 후보를 암시한다.
assistant_recovery.tmp는 Windows Recovery Assistant 관련 분기 또는 루프 엔딩 후보로 활용할 수 있다.
주의점
Stage 9에서는 암시를 강하게 넣어도 되지만, 정체를 직접 공개하지 않는다.
“당신은 사용자다”, “네가 시스템을 망가뜨렸다”, “복구 프로그램은 거짓이다” 같은 표현은 Stage 10까지 미룬다.
실제 사용자 이름을 문서나 예시에 넣지 않는다.
모든 예시는 “입력한 이름”, “복구 프로필 이름”, “ProfileName”, “Player” 같은 일반 표현으로 쓴다.
Stage 9의 마지막 감정은 완전한 공포보다 “이제 거의 알 것 같은데 아직 말해주지 않는 불편함”에 가깝게 잡는다.
