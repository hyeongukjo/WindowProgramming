STAGE 10 최종[Recycle Bin 던전]
스테이지 한 줄 요약
Stage 10은 지금까지 정리·삭제·격리·차단·닫기 행동이 모두 휴지통에 모이고, 플레이어가 직접 삭제할 대상을 입력해 엔딩이 갈리는 최종 스테이지다.

핵심 컨셉
Stage 10은 지금까지 플레이어가 정리했다고 믿었던 모든 항목이 모이는 최종 스테이지이다.
Stage 9에서 Temp Cache의 파일들이 Recycle Bin으로 이동했기 때문에, Stage 10은 “모든 삭제된 항목의 최종 보관소”로 자연스럽게 이어진다.
겉으로는 휴지통을 비우는 마지막 복구 작업처럼 보이지만, 실제로는 플레이어가 지금까지 닫고, 미루고, 차단하고, 삭제한 행동들과 마주하는 장면이다.
최종부에서는 플레이어가 직접 “삭제할 프로세스 이름”을 입력하고, 입력값에 따라 엔딩이 갈린다.
반전은 긴 설명이 아니라, 플레이어가 직접 입력하는 행위를 통해 완성되어야 한다.
Stage 10에서 지켜야 할 점
Stage 1~9에서 쌓아온 파일명, 기록, 보스 이름, 입력한 이름을 모두 회수한다.
처음에는 Illegal_Binny가 최종 보스처럼 보이게 한다.
Illegal_Binny 처치 이후 진짜 갈등은 Windows Recovery Assistant와 최종 입력창으로 넘어간다.
플레이어가 Stage 1에서 입력한 복구 프로필 이름을 입력하면 진엔딩으로 분기한다.
보스 이름을 입력하면 문제를 외부 대상으로 돌리는 일반 엔딩으로 분기한다.
Windows Recovery Assistant를 입력하면 Assistant 루프 엔딩으로 분기한다.
존재하지 않는 이름이나 빈칸을 입력하면 짧은 실패 엔딩으로 처리한다.
실제 사용자 이름은 문서나 예시에 넣지 않는다. 반드시 “입력한 이름”, “복구 프로필 이름”, “ProfileName”으로 표기한다.
2. 스테이지 진행 구조
진행 요약
Stage 10은 Stage 9에서 정리된 임시파일과 캐시가 모두 Recycle Bin으로 이동했다는 알림으로 시작된다.
플레이어는 Recycle Bin 던전에 진입해 삭제된 파일, 오류 보고서, 보스 잔여 데이터, 복구 프로필 기록을 확인한다.
처음에는 Illegal_Binny를 최종 보스로 상대하지만, Illegal_Binny가 격리된 뒤 최종 입력창이 나타난다.
최종 입력창에서는 삭제할 프로세스 이름을 플레이어가 직접 입력한다.
입력값에 따라 진엔딩, 일반 엔딩, Assistant 루프 엔딩, 잘못된 입력 엔딩으로 갈린다.

3. 진입 연출
장면 목적
Stage 9에서 Temp Cache의 항목들이 Recycle Bin으로 이동한 직후, 최종 정리 구역으로 진입하는 장면이다.
플레이어는 아직 “마지막으로 휴지통을 비우면 복구가 끝난다”고 믿어야 한다.
하지만 화면은 이미 Stage 1의 밝은 휴지통과 달리 무겁고 불편한 분위기를 가져야 한다.
화면 구성

휴지통 아이콘 안쪽에서 Stage 9에서 이동한 임시파일 조각들이 희미하게 보인다.
플레이어가 휴지통 근처로 이동하면 상호작용 표시가 뜬다.

4. Recycle Bin 던전 화면 구성
장면 목적
지금까지 삭제되거나 격리된 모든 항목이 휴지통 안에 모여 있음을 보여주는 장면이다.
이 공간은 단순한 쓰레기통이 아니라, 플레이어가 처리했다고 믿은 것들이 마지막으로 보관된 장소처럼 보여야 한다.
화면 구성
휴지통 창 안쪽은 거대한 저장소처럼 확장되어 있다.
바닥에는 삭제된 파일 조각, 임시 보고서, 오래된 바로가기, 캐시 파일, 드라이버 조각, 오류창 조각이 쌓여 있다.
벽면에는 Stage 1~9에서 봤던 파일명과 시스템 기록이 흐릿하게 붙어 있다.
작업 표시줄에는 닫힌 창 버튼들이 비정상적으로 많이 쌓여 있다.
배경음은 거의 사라지고, 파일 삭제음과 오류음이 낮게 반복된다.
휴지통 내부에 보이는 항목 예시
새 폴더 조각
진짜최종_수정_최종_진짜.ppt
Driver-K.log
High-Kernel.protect
BSOD_dump.tmp
ExceptionQueen.err
UNSENT_REPORT.tmp
profile_입력한 이름.cache
assistant_recovery.tmp
Illegal_Binny.dat
비고
이 항목들은 대사로 설명하지 않고 파일명, 로그, 오브젝트 형태로 보여준다.
플레이어가 지금까지의 행동과 보스들을 자연스럽게 떠올릴 수 있게 하는 것이 목적이다.
5. 이전 스테이지 회수 요소
장면 목적
Stage 10은 지금까지의 모든 스테이지를 회수하는 최종 스테이지이므로, 각 스테이지의 핵심 오브젝트와 기록이 휴지통 안에 흩어져 있어야 한다.
구간
회수 요소
Stage 1
복구 프로필 이름, 새 폴더, 진짜최종 파일, 휴지통 비우기

Driver-K, Unknown Device, 드라이버 충돌 기록
Stage 3
업데이트 연기, 나중에, 15분 후 알림, 재시작 지연
Stage 4
추가 권한 허용, System32 접근 기록, High-Kernel
Stage 5
차단된 연결, PortBlocked, localhost 또는 unknown-port 기록
Stage 6
Crash Dump, BSOD, System Stability Failure
Stage 7
ProfileName, RecentActions, LastSession
Stage 8
확인 / 취소 / 나중에 / 닫기, Exception Queen, UNSENT_REPORT
Stage 9
임시파일, 캐시, 삭제된 항목이 Recycle Bin으로 이동됨, 보스 이름 후보들
표현 방식
이 요소들을 Assistant가 직접 설명하지 않는다.
휴지통 안의 파일명, 시스템 로그, 삭제된 항목 목록, 흐릿한 오브젝트로 보여준다.
플레이어가 스스로 “이것들이 전부 내가 지나온 흔적이다”라고 느끼게 만드는 것이 핵심이다.
6. 표면상 최종 보스: Illegal_Binny
장면 목적
Illegal_Binny는 Stage 10 초중반의 표면상 최종 보스이다.
플레이어는 처음에 Illegal_Binny를 없애면 복구가 끝날 것이라고 믿는다.
하지만 Illegal_Binny는 진짜 최종 갈등이 아니라, 지금까지 삭제된 항목들이 뭉친 결과물이다.
보스 의미
Illegal_Binny는 휴지통 안에 쌓인 삭제된 파일, 오류 보고서, 임시파일, 보스 잔여 데이터가 뭉친 존재다.
그는 지금까지 플레이어가 닫고, 정리하고, 미루고, 차단하고, 삭제한 것들이 완전히 사라지지 않았음을 보여준다.
Illegal_Binny는 악당처럼 보이지만, 사실상 “삭제된 항목들의 집합”이다.
보스 외형
거대한 휴지통 아이콘이 괴물처럼 변형된 형태
몸체는 찢어진 파일, 오류창, 임시파일, 보스 잔여 데이터가 섞여 있음
뚜껑은 입처럼 열리고 닫힘
몸 주변에 Driver-K, High-Kernel, BSOD, Exception Queen의 잔여 아이콘이 떠 있음
중심부에는 “Illegal_Binny.dat” 파일명이 깜빡임
공격할 때마다 삭제음, 오류음, 휴지통 비우기 효과음이 섞여 들림

7. Illegal_Binny 최종 전투
장면 목적
Illegal_Binny와의 전투는 지금까지의 정리 작업을 모두 압축한 최종 전투처럼 보여야 한다.
플레이어는 삭제된 항목 더미를 피해 움직이고, 보스 잔여 데이터들을 정리하며 Illegal_Binny의 중심부에 접근한다.
전투 공간
전투는 Recycle Bin 던전 내부에서 진행된다.
휴지통 내부의 파일 더미가 벽과 발판이 된다.
삭제된 오류창 조각은 장애물처럼 튀어나오고, 보스 잔여 데이터는 공격 패턴처럼 움직인다.
전투 중 화면 하단 작업 표시줄에는 닫힌 창 버튼들이 계속 쌓인다.

전투 관련 메모

이 문서에서는 최종 보스전의 감정, 화면 구성, 연출 방향을 우선 정리한다.

9. 최종 입력창 등장
장면 목적
Stage 10의 핵심 장면이다.
플레이어가 직접 삭제할 프로세스 이름을 입력하며, 이 입력값에 따라 엔딩이 갈린다.
반전은 설명으로 주어지는 것이 아니라 플레이어가 무엇을 입력해야 하는지 스스로 고민하는 과정에서 완성되어야 한다.
화면 구성

17. Stage 10 기획 메모
핵심 주제
Stage 10은 “보스 처치”가 아니라 책임의 방향을 어디로 돌리느냐가 핵심이다.
보스 이름을 입력하면 문제를 외부 대상으로 돌리는 것이고, 입력한 이름을 입력하면 현재 세션의 원인을 자기 자신에게서 찾는 것이다.
Windows Recovery Assistant를 입력하면 도우미를 의심하지만, 도우미는 복구 절차에 의해 보호되어 루프로 돌아간다.
멀티엔딩 구조 요약
보스 이름 입력: 문제를 외부 대상으로 돌림 -> 일반 엔딩 / 루프
Stage 1에서 입력한 복구 프로필 이름 입력: 현재 세션을 종료함 -> 진엔딩
Windows Recovery Assistant 입력: 도우미 삭제 시도 실패 -> Assistant 루프 엔딩
존재하지 않는 이름 입력: 대상 탐색 실패 -> 잘못된 입력 엔딩
후반 회수 방식
Stage 1의 복구 프로필 이름을 최종 입력 조건으로 회수한다.
Stage 2~8의 보스 이름을 일반 엔딩 입력 후보로 회수한다.
Stage 9의 임시파일과 캐시를 최종 입력 후보 힌트로 사용한다.
Stage 8의 닫기, 확인, 취소, 나중에 행동을 Illegal_Binny와 Exception Queen 잔여 대사로 회수한다.
Stage 4의 [허용]과 Stage 5의 [차단] 기록은 휴지통 내부 로그로 보여준다.
주의점
문서와 예시에는 실제 사용자 이름을 넣지 않는다.
진엔딩 조건은 항상 “Stage 1에서 입력한 복구 프로필 이름” 또는 “입력한 이름”으로 표기한다.
최종 반전은 Assistant의 장문 설명보다 플레이어의 직접 입력과 시스템 메시지로 보여준다.
진엔딩은 완전한 복구가 아니라 반복 종료에 가깝게 연출한다.
일반 엔딩은 겉보기 복구처럼 보이지만 Stage 1로 돌아가는 루프성 엔딩으로 처리한다.
