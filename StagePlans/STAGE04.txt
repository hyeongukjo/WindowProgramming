핵심 컨셉
Stage 4는 플레이어가 처음으로 “함부로 들어가면 안 되는 시스템 핵심 구역”에 진입하는 스테이지이다.
Stage 1~3이 비교적 유쾌한 Windows XP 패러디에 가까웠다면, Stage 4부터는 분위기가 조금 차가워진다.
System32는 시스템 핵심 파일들이 보관된 구역이며, 플레이어는 무결성 검사를 위해 이곳에 진입한다.
하지만 System32 내부를 지키는 보안 개체 High-Kernel이 플레이어의 접근을 위험한 작업으로 판단하고 차단한다.
Stage 4에서 지켜야 할 점
일반 몹전은 넣지 않는다.
보스전 하나에 집중한다.
화면은 반드시 Windows XP 탐색기 / 시스템 폴더 느낌을 유지한다.
Stage 1~3보다 조용하고 차가운 분위기를 준다.
Windows Recovery Assistant의 말투는 아직 친절하지만, 이전보다 조금 더 기계적이어야 한다.
“사용자”, “범인”, “정체” 같은 직접적인 반전 암시는 넣지 않는다.
“관리자 권한”이라는 표현은 가능하면 직접 쓰지 않고, “추가 권한”, “보호된 영역”, “접근 제한” 정도로 순화한다.
2. 스테이지 진행 구조
진행 요약
Stage 4는 Stage 3 클리어 후 생성된 System32 Check.exe를 실행하면서 시작된다.
플레이어는 Windows XP 탐색기 형태의 System32 구역에 진입한다.
처음에는 단순한 시스템 파일 무결성 검사처럼 보이지만, 곧 핵심 파일 보호 절차가 작동하며 High-Kernel이 등장한다.
High-Kernel은 System32 핵심 파일을 보호하는 경비 프로그램이다.
플레이어는 High-Kernel과 보스전을 진행하고, 전투 후 핵심 파일 무결성 검사를 완료한다.

무섭게 몰아붙이기보다는 “조용하고 불편한 긴장감”을 주는 것이 중요하다.

장면 목적

4. System32 화면 구성
장면 목적
System32 금지구역의 시각적 분위기를 보여주는 장면이다.
Stage 1의 바탕화면처럼 활기차지 않고, 정렬된 파일들이 너무 조용하게 놓여 있어 불편한 느낌을 준다.
화면 구성
화면 중앙에는 Windows XP 탐색기 창이 크게 열린다.
창 제목은 System32이며, 주소창에는 C:\WINDOWS\system32 경로가 표시된다.
파일 목록 예시
kernel32.dll
shell32.dll
hal.dll
ntoskrnl.exe
config
drivers
cmd.exe
taskmgr.exe
winlogon.exe
services.exe
화면 연출
파일들은 움직이지 않는다. 아이콘도 흔들리지 않는다.
Stage 1의 파일 괴물들과 달리, 이 구역의 파일들은 지나치게 정돈되어 있다.
탐색기 창 안쪽은 약간 차가운 회색빛으로 보인다.
마우스를 올린 파일마다 짧은 정보창이 뜨지만, 대부분 “보호된 시스템 파일”이라는 문구가 표시된다.
user32.dll은 실제 Windows 시스템 파일이지만, 이름이 후반 반전을 너무 빨리 떠올리게 할 수 있으므로 Stage 4 문서에서는 강조하지 않는다.
목록에 넣더라도 화면에 잠깐 지나가는 정도로만 사용한다.
5. Windows Recovery Assistant 안내
장면 목적
System32 구역의 성격을 설명하고, 이전보다 조금 차가워진 Windows Recovery Assistant의 톤을 보여준다.

모니터 화면에는 평소처럼 웃는 얼굴이 표시되지만, 표정이 Stage 1~2보다 조금 덜 활발하다.

6. 접근 제한 이벤트
장면 목적
High-Kernel 등장 전에 System32가 보호된 공간이라는 점을 보여주는 장면이다.
플레이어가 “여기는 평소처럼 정리하면 안 되는 곳 같다”는 불편함을 느끼게 한다.
진행
플레이어가 탐색기 창 안쪽으로 이동하면 특정 파일들이 선택 불가능한 상태로 보인다.
kernel32.dll, hal.dll, ntoskrnl.exe 주변에 희미한 보호막이 생긴다.
파일 하나를 조사하려고 하면 Windows XP 스타일 경고창이 열린다.
시스템 경고
보호된 시스템 파일
이 파일은 Windows가 정상적으로 작동하는 데 필요합니다.
수정하거나 이동하지 않는 것이 좋습니다.
[확인]
플레이어가 [확인]을 누르면 파일 주변 보호막이 더 선명해진다.
탐색기 창 상단에 “검사 진행 중...” 메시지가 표시된 뒤, 잠시 후 “접근 권한 확인 중...”으로 바뀐다.
비고
이 장면에서는 “관리자 권한”이라는 단어를 직접 쓰지 않는다.
대신 “접근 권한”, “보호된 파일”, “추가 권한” 같은 표현을 사용한다.
7. 보스 등장: High-Kernel
장면 목적
System32의 경비병 역할을 하는 보스 High-Kernel을 등장시키는 장면이다.
High-Kernel은 악성 프로그램이 아니라 시스템 핵심 파일을 지키는 보호 개체다.
하지만 플레이어의 복구 명령을 안전하지 않은 접근으로 판단하고 전투를 시작한다.
화면 구성
탐색기 창 안쪽의 파일 목록이 멈춘다.
kernel32.dll, hal.dll, ntoskrnl.exe 파일 아이콘이 하나씩 떠오른다.
파일 아이콘들이 원형으로 회전하며 보호막을 만든다. 그 중심에서 High-Kernel이 나타난다.
보스 외형
몸체는 금속성 시스템 코어처럼 보임
중심부에 파란색 커널 아이콘 또는 회로 문양이 있음
주변에 DLL 파일 아이콘들이 방패처럼 회전함
얼굴은 거의 없고, 작은 상태 표시등만 있음
움직임이 느리고 무겁다
공격할 때마다 보안 경고창과 접근 제한 메시지가 나타남
체력이 낮아질수록 파일 보호막이 하나씩 깨짐
첫 번째 보안 경고
보스 대사는 일반 말풍선이 아니라 보안 경고창으로 표시된다.
보안 경고
High-Kernel

[확인]

High-Kernel은 감정적으로 화를 내는 보스가 아니다.
차갑고 규칙적인 시스템 경비병처럼 행동한다.
그 차가움이 Stage 4의 분위기 변화를 만들어야 한다.
8. 보스전 구간
장면 목적
High-Kernel과의 보스전을 진행하는 장면이다.
Stage 2의 Driver-K가 공격적인 드라이버 보스였다면, High-Kernel은 방어적이고 권한 중심의 보스다.
전투 공간
전투는 System32 탐색기 창 내부에서 진행된다.
파일 목록은 전투 필드의 벽과 장애물처럼 작동한다.
회전하는 DLL 파일들은 High-Kernel의 보호막 역할을 한다.
자물쇠 아이콘과 경고창은 공격 예고 또는 방어 상태를 표시한다.

[확인]
플레이어는 High-Kernel을 직접 공격하기보다, 주변을 돌고 있는 보호 파일들을 먼저 약화시켜야 한다.
보호막이 약해지면 High-Kernel 본체에 피해가 들어간다.
구체적인 보스 패턴과 수치는 아직 확정하지 않는다.
임시 보스 패턴 방향
보호 파일 회전 - DLL 파일 아이콘들이 High-Kernel 주변을 돌며 공격을 막는다.
접근 거부 - 플레이어의 공격을 일정 시간 차단한다.
파일 잠금 - 특정 구역을 자물쇠 아이콘으로 막아 이동을 제한한다.
권한 확인 - 전투 중간에 추가 권한 확인창이 나타난다.
시스템 경고 - 공격 직전에 경고창 또는 붉은 테두리 표시가 나타난다.
비고
패턴 이름과 수치는 임시 방향이다.
Stage 4 문서에서는 보스의 이미지, 등장 방식, 전투 흐름, 분위기를 우선 정리한다.
세부 패턴은 추후 전투 시스템 설계 단계에서 조정한다.
9. 추가 권한 확인 이벤트

10. 보스전 중간 연출
장면 목적
High-Kernel이 단순한 악당이 아니라, 시스템을 지키는 존재라는 점을 약하게 보여주는 장면이다.

14. Stage 4 기획 메모
핵심 감각
핵심 감각
Windows XP 탐색기 안의 System32 폴더에서
시스템 핵심 파일을 보호하는 High-Kernel과 대치하는
조용하고 차가운 첫 긴장 구간
분위기 변화
Stage 1은 밝고 유쾌한 바탕화면 정리였다.
Stage 2는 장치 충돌을 활용한 첫 보스전이었다.
Stage 3은 업데이트 지연과 반복 알림의 스트레스를 보여줬다.
Stage 4는 처음으로 조용한 긴장감과 접근 제한의 불편함을 보여준다.
보스 의미
High-Kernel은 단순한 악성 프로그램이 아니다.
System32 핵심 파일을 보호하는 보안 경비병이다.
플레이어의 복구 명령을 안전하지 않은 접근으로 판단하고 보호 절차를 시작한다.
전투 중에는 차갑고 위압적인 보스처럼 보이지만, 본질적으로는 시스템을 지키려는 존재다.
NPC 표현 방식
Windows Recovery Assistant는 Stage 1~3과 동일하게 캐릭터가 포함된 Windows XP 스타일 알림창으로 대사를 전달한다.
다만 Stage 4부터는 말투가 조금 더 딱딱하고 기계적으로 변한다.
밝은 감탄사와 농담을 줄이고, 시스템 안정성, 접근 권한, 보호 절차 같은 표현을 사용한다.
전투 관련 메모
Stage 4는 보스 스테이지이므로 일반 몹전은 넣지 않는다.
High-Kernel 하나에 집중한다.
구체적인 공격 패턴, 피해량, 스킬 상성, 쿨타임은 아직 확정하지 않는다.
이 문서에서는 보스의 이미지, 등장 방식, 전투 흐름, 클리어 연출을 우선 정리한다.
후반 회수 가능 요소
Stage 4의 [허용] 버튼은 후반부에서 회수할 수 있다.
초반에는 단순한 전투 기믹처럼 보이지만, 후반부에서는 플레이어가 여러 차례 시스템 접근 권한을 허용했다는 기록으로 다시 등장할 수 있다.
단, Stage 4에서는 이 의미를 직접 설명하지 않는다.
주의점
Stage 4에서는 후반 반전을 직접 암시하지 않는다.
“사용자”, “관리자 정체”, “너는 범인이다”, “User_Session.exe”, “shutdown”, “taskkill” 같은 요소는 사용하지 않는다.
다만 이전 스테이지보다 조금 더 차갑고 불편한 분위기를 만든다.
