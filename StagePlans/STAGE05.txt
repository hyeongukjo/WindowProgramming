핵심 컨셉
Stage 5는 Windows XP의 네트워크 연결, 방화벽, 포트, 패킷을 활용한 일반 스테이지이다.
플레이어는 불필요한 포트를 차단하고, 이상 패킷을 제거하며, 네트워크 연결을 안정화한다.
겉으로는 보안 작업처럼 보이지만, 실제 플레이 감각은 “연결을 하나씩 끊어가는 행위”에 가깝다.
Stage 4에서 시작된 차갑고 불편한 분위기를 이어가되, 일반 스테이지답게 움직임과 전투 밀도를 높인다.
Stage 5에서 지켜야 할 점
일반 스테이지이므로 일반 전투 구간을 넣는다.
Stage 1의 바탕화면 전투, Stage 3의 진행률 구간과 다른 플레이 감각을 제공한다.
네트워크 항구를 이동하며 포트를 확인하고, 패킷 흐름을 정리하는 구조로 만든다.
Windows XP 네트워크 연결창, 방화벽 설정창, 포트 번호, 패킷 표시를 적극 활용한다.
CMD 직접 입력은 아직 사용하지 않거나 최소화한다.
Windows Recovery Assistant는 Stage 4보다 조금 더 기계적인 안내 톤을 유지한다.
후반 반전을 직접 암시하지 않는다.
2. 스테이지 진행 구조
진행 요약
Stage 5는 Stage 4 클리어 후 생성된 Network Port.exe를 실행하면서 시작된다.
플레이어는 Windows XP 네트워크 연결 창이 항구처럼 확장된 공간에 진입한다.
항구 안에는 포트 번호가 적힌 부표, 흐르는 패킷, 방화벽 게이트, 네트워크 케이블 오브젝트가 배치되어 있다.
플레이어는 열린 포트를 정리하고, 이상 패킷을 제거한 뒤, 방화벽 게이트를 통해 마지막 연결 과부하 구간을 안정화한다.
주요 진행 순서
Network Port.exe 실행
Network Connections 화면 진입
Network Port 항구 화면 구성 확인
열린 포트 정리 구간
이상 패킷 제거 구간
방화벽 게이트 이벤트
연결 과부하 정리 구간
네트워크 안정화 완료
다음 스테이지 Blue Screen Tower로 연결
비고
Stage 5는 “외부 연결을 차단한다”는 명분을 가진 스테이지이다.
다만 아직 반전을 직접 설명하지 않고, 플레이어가 보안 작업처럼 받아들이게 만든다.

장면 목적

Stage 4의 조용한 긴장감을 유지하면서도, 새 스테이지의 공간감은 더 넓고 움직임 있게 보여준다.

창 내부가 물결처럼 흔들리며 항구 형태의 전투 공간으로 확장된다.
4. Network Port 항구 화면 구성
장면 목적
Stage 5의 전투 공간을 소개하는 장면이다.
Windows XP 네트워크 연결 UI를 항구처럼 변형해, 포트와 패킷을 시각적으로 이해하기 쉽게 만든다.
화면 구성
화면 중앙에는 Windows XP 스타일 네트워크 연결 창이 크게 열린다.
창 제목은 다음과 같다.
창 제목
Network Connections
창 내부에는 네트워크 항구처럼 보이는 전투 공간이 펼쳐진다.
포트 번호가 적힌 부표가 물 위에 떠 있음
작은 패킷들이 물고기나 작은 배처럼 이동함

인터넷 연결 아이콘이 등대처럼 깜빡임
연결 상태 아이콘이 파도처럼 흔들림

분위기
Stage 5는 Stage 4보다 움직임이 많지만, 밝은 분위기로 완전히 돌아가면 안 된다.
차가운 파란색 네트워크 화면과 연결 차단 UI를 통해 약한 불편함을 유지한다.
5. Windows Recovery Assistant 안내
장면 목적
Network Port 항구의 문제 상황을 설명하고, Stage 4 이후 조금 더 기계적으로 변한 Assistant의 톤을 보여준다.
화면 구성
화면 오른쪽 아래에 Windows Recovery Assistant 알림창이 열린다.
알림창 왼쪽에는 CRT 모니터 머리의 Windows Recovery Assistant 캐릭터가 들어 있다.
모니터 화면에는 안내 표정이 표시되지만, Stage 1보다 움직임은 적다.
알림창
Windows Recovery Assistant
Network Port 항구에 진입했습니다.
현재 여러 개의 외부 연결이 감지되고 있습니다.
불필요한 연결은 시스템 안정성을 위해 차단하는 것이 좋습니다.
[확인]
진행
플레이어가 [확인]을 누르면 항구 안쪽의 포트 부표들이 하나씩 깜빡인다.
알림창
Windows Recovery Assistant
연결 상태를 분류하는 중입니다.
정상 패킷과 이상 패킷을 구분하여 처리해주세요.
[확인]
비고
Assistant는 여전히 플레이어를 돕고 있지만, Stage 1~2보다 표현이 덜 감정적이다.
“안전하지 않을 수 있습니다”, “차단하는 것이 좋습니다”처럼 시스템 안내문에 가까운 말투를 사용한다.
6. 일반 전투 구간 1: 열린 포트 정리
장면 목적
Stage 5의 첫 전투 구간이다.
플레이어가 포트 번호가 표시된 적을 정리하면서, 네트워크 항구의 기본 전투 감각을 익히게 한다.
화면 구성
항구 입구에는 포트 번호가 적힌 부표들이 떠 있다.
일부 부표는 초록색으로 안정되어 있고, 일부는 노란색 또는 빨간색으로 깜빡인다.
주요 적
Open Port Buoy
열린 포트가 부표처럼 떠다니는 적이다.
포트 번호가 몸체에 표시된다.
예: 21, 23, 80, 443, 8080
공격받으면 포트 번호가 깜빡인다.
일정 시간 방치하면 다른 연결 개체를 불러오는 느낌을 준다.
전투 흐름
플레이어는 Recovery Program 캐릭터를 움직여 열린 포트 부표에 접근한다.
기본 공격 또는 임시 스킬을 사용해 불안정한 포트를 정리한다.
정상 포트와 이상 포트의 구분 방식, 공격 패턴, 수치는 아직 확정하지 않는다.
비고
Stage 5의 첫 구간이므로 난이도는 낮게 유지한다.
포트 번호와 색상 변화만으로도 네트워크 개념이 시각적으로 전달되게 한다.
7. 일반 전투 구간 2: 이상 패킷 제거
장면 목적
Stage 5의 두 번째 일반 전투 구간이다.
정적인 포트 정리에서 벗어나, 빠르게 흐르는 패킷을 따라가며 제거하는 플레이 감각을 준다.
화면 구성
항구 안쪽으로 이동하면 패킷 흐름이 강해진다.
작은 패킷들이 물고기나 작은 배처럼 한 방향으로 이동한다.
일부 패킷은 정상 신호처럼 보이고, 일부 패킷은 이상 신호처럼 깜빡인다.
주요 적
Packet Minnow
작은 패킷 물고기 같은 적이다.
여러 마리가 빠르게 지나간다.
직접 공격보다 경로 차단과 추적이 중요하다.
일부는 정상 패킷처럼 보이고, 일부는 이상 패킷처럼 보인다.
전투 흐름
플레이어는 흐르는 패킷 중 이상 패킷을 우선 처리한다.
패킷이 화면 밖으로 빠져나가면 네트워크 상태가 일시적으로 불안정해지는 연출을 넣을 수 있다.
정상 패킷과 이상 패킷의 구분은 지나치게 어렵게 만들지 않는다.
알림창
Windows Recovery Assistant
알 수 없는 연결은 안전하지 않을 수 있습니다.
확실하지 않은 연결은 차단하는 편이 안전합니다.
[확인]
비고
이 대사는 후반부에서 회수할 수 있는 문장이다.
하지만 Stage 5에서는 단순한 보안 안내처럼 보이게 해야 한다.
8. 방화벽 게이트 이벤트
장면 목적
Stage 5의 중간 이벤트이다.
플레이어가 네트워크 연결을 직접 “차단”하거나 “허용”하는 UI를 조작하게 만든다.
화면 구성
항구 중앙에 방화벽 설정창처럼 생긴 큰 게이트가 나타난다.
게이트에는 Windows XP 스타일 버튼이 표시된다.
방화벽 게이트
[차단] [허용] [나중에 결정]
주요 적 / 장애물
Firewall Barnacle
방화벽 게이트에 달라붙은 따개비 같은 적이다.
직접 이동하지 않는다.
방화벽 게이트를 막고 있다.
제거해야 다음 구역으로 이동할 수 있다.
Request Crab
요청 신호가 게처럼 옆으로 걷는 적이다.
플레이어 주변에 작은 연결창을 띄운다.
“연결을 허용하시겠습니까?” 같은 팝업으로 이동을 방해한다.
진행
플레이어는 방화벽 게이트 주변의 장애물을 정리한다.
게이트가 활성화되면 연결 설정 확인창이 열린다.
시스템 확인창
Windows Firewall
알 수 없는 연결 요청이 감지되었습니다.
이 연결을 어떻게 처리하시겠습니까?
[차단] [허용] [나중에 결정]
플레이어 조작
플레이어가 [차단]을 선택하면 게이트가 닫히며 다음 구역으로 이동할 수 있다.
플레이어가 [허용]을 선택하면 일부 패킷이 통과하고, 잠시 후 다시 확인창이 뜰 수 있다.
[나중에 결정]은 Stage 3의 업데이트 연기처럼 잠시 문제를 미루는 선택으로 사용할 수 있다.
비고
이 선택은 후반부에서 연결 차단 기록으로 회수할 수 있다.
하지만 Stage 5에서는 보안 설정을 조정하는 일반적인 UI처럼 보여야 한다.
9. 일반 전투 구간 3: 연결 과부하
장면 목적
Stage 5의 마지막 일반 전투 구간이다.
포트 정리, 패킷 제거, 방화벽 조작을 모두 사용해 네트워크 연결 과부하를 안정화한다.
화면 구성
방화벽 게이트를 지나면 항구 끝에 큰 연결 허브가 보인다.
허브 주변에는 네트워크 케이블과 패킷 흐름이 복잡하게 얽혀 있다.
연결 상태 표시가 빠르게 변한다.
네트워크 상태
Packets Sent: 증가 중
Packets Received: 증가 중
Unknown Connections: 증가 중
Firewall: Enabled
전투 흐름
플레이어는 열린 포트와 이상 패킷을 동시에 정리한다.
일부 Request Crab이 연결 확인창을 띄워 플레이어의 이동을 방해한다.
Firewall Barnacle을 제거하면 방화벽 게이트가 정상적으로 닫힌다.
모든 연결 과부하가 줄어들면 항구의 파도와 패킷 흐름이 안정된다.
임시 전투 방향
적의 구체적인 공격 패턴과 수치는 아직 확정하지 않는다.
Stage 5는 디펜스 요소가 섞인 액션 전투로 설계한다.
적을 모두 따라가서 잡는 방식보다, 흐름을 막고 게이트를 조작하는 재미를 강조한다.
정상 패킷과 이상 패킷 구분은 너무 어렵게 만들지 않는다.
10. 전투 종료 흐름
장면 목적
Network Port 항구의 연결 과부하를 안정화하고, 스테이지를 마무리하는 장면이다.
진행
열린 포트들이 하나씩 닫힌다.
불안정하게 흐르던 패킷들이 정렬된 경로로 이동한다.
방화벽 게이트가 천천히 닫히고, 항구 입구에 “Firewall: Enabled” 표시가 고정된다.
화면 구성
네트워크 상태
Local Area Connection
Status: Connected
Packets Sent: 안정됨
Packets Received: 안정됨
Firewall: Enabled
Unknown Connections: 차단됨
미묘한 기록 연출
전투 종료 직후, 네트워크 기록창이 아주 짧게 스쳐 지나간다.
최근 연결 기록
최근 연결:
192.168.0.12
update.server
localhost
unknown-port
상태: 일부 연결 차단됨
비고

13. Stage 5 기획 메모
핵심 감각
핵심 감각
Windows XP 네트워크 연결창이 항구처럼 변형되고
플레이어가 포트와 패킷을 정리하며
연결을 차단해 시스템을 안정화하는 디펜스형 일반 스테이지
분위기 변화
Stage 4는 조용한 접근 제한과 권한 확인의 불편함을 보여줬다.
Stage 5는 그 불편함을 유지하되, 네트워크 항구라는 더 넓고 움직임 있는 공간으로 전환한다.
초반에는 네트워크 오류를 고치는 느낌이고, 후반에는 차단과 허용 선택이 반복되며 묘하게 불편한 느낌을 준다.
주요 적 의미
Stage 5의 적들은 단순한 바이러스가 아니다.
Open Port Buoy, Packet Minnow, Request Crab, Firewall Barnacle은 각각 열린 포트, 흐르는 패킷, 연결 요청, 방화벽 장애물을 시각화한 존재다.
플레이어는 이들을 정리하면서 네트워크를 안정화한다고 믿지만, 동시에 여러 연결을 차단하게 된다.
NPC 표현 방식
Windows Recovery Assistant는 Stage 4의 기계적인 톤을 일부 유지한다.
아직 공격적이거나 집착적인 말투는 아니지만, “차단하는 편이 안전합니다”처럼 시스템 안정성을 우선하는 표현을 사용한다.
전투 관련 메모
Stage 5는 일반 스테이지이므로 일반 전투 구간을 넣는다.
세부 공격 패턴, 피해량, 스킬 상성, 쿨타임은 아직 확정하지 않는다.
이 문서에서는 전투의 화면 구조, 적 이미지, 구간별 플레이 감각을 우선 정리한다.
Stage 1처럼 한 화면에 파일 적이 등장하는 방식과 다르게, 항구 구역을 이동하며 전투가 진행되도록 한다.
후반 회수 가능 요소
방화벽 게이트의 [차단] 선택은 후반부에서 연결 차단 기록으로 회수할 수 있다.
최근 연결 목록의 localhost는 후반부에서 의미를 가질 수 있다.
Stage 5에서는 이 요소들을 강조하지 않고, 단순한 네트워크 기록처럼 지나가게 한다.
주의점
Stage 5에서는 후반 반전을 직접 암시하지 않는다.
“사용자”, “관리자 정체”, “너는 범인이다”, “User_Session.exe”, “shutdown”, “taskkill” 같은 요소는 사용하지 않는다.
보안 작업처럼 보이지만, 연결을 끊는 행위라는 불편함만 약하게 남긴다.
